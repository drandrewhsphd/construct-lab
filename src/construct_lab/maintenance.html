Back up your work

A verified database backup includes every project's imported PDFs, extracted text, coding, definitions, evidence rounds and decision history. A backup is also created each time the launcher starts a new server.

Backups are saved in the app folder under data/backups. Copy that folder to your own secure external storage for protection against computer loss. These local backups are not cloud backups.

Standalone reports outside the database and session-only API keys are not included. No research data or credentials are sent to GitHub.

Restore a backup

  1. Save any open edits, then click Stop app for recovery below.
  2. In the app folder, double-click Restore Construct Lab.command.
  3. If the recovery tool detects an older prototype server, restart the computer and run Restore before opening the app. Select the backup number. Type RESTORE when prompted. The tool verifies the backup and saves the current database before replacing it.
  4. Double-click Open Construct Lab.command, then return to http://127.0.0.1:8780/.

Restoring replaces all projects with their state at the backup time. The safety backup lets you recover the pre-restore state.

Everyday use

Open the app with Open Construct Lab.command. Use the single Home address and choose your project. Work saves when you click the relevant Save button; unsaved edits are not backed up. After restarting, reconnect the AI provider in Extract if needed.

This remains a local, single-user app. GitHub stores application code separately from your research database.
